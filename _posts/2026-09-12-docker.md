**Containers are a form of software isolation. They have their own filesystem for isolating installed apps, libraries, runtime environment/interpreter/compiler, etc. Unlike VMs which have their own kernel, containers share the host kernel: this makes them more lightweight (shared memory, process management, etc), but also less secure since vulnerabilities can propagate from the host OS to the container and vice versa. There is also isolation for processes and networking. Resources can also be assigned to containers, though ultimately resource management is still common to all containers on the same machine since they share the host kernel.**

## Docker commands:

- Build image: `docker build -t <name> <path to directory where dockerfile lives>`
- If dockerfile is not named ‘Dockerfile’: `docker build -t <name> -f <path to dockerfile>`
- List images: `docker image ls`
- List all running containers: `docker ps`
- Run an image: `docker run [OPTIONS] <image name>`
    - To override: `docker run [OPTIONS] <image name> [COMMAND] [ARG]`
        - CMD (defined in the Dockerfile) doesn’t run anymore, it instead runs COMMAND with args ARG
    - [OPTIONS]: optional, can include…
        - `-d`: detach, will keep running even when you close your terminal
        - `-t <image name>`: assign name to image
        - `-it`: starts an interactive terminal
        - `-p <your port number>:<container port number>`: if you visit `https://localhost:<your port number>`, will route traffic to the container port number
        - `--rm` (auto-remove container after running)
- Stop a container: `docker stop <container name>`
- Delete a container: `docker rm <container name>`
