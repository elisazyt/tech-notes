**An HPC cluster is multiple nodes (high-performance computers) connected through high-speed network to distribute/parallelize tasks. It provide CPU (more cores than regular computer) or GPU, and more RAM.**

## Basics
- Node types:
  - Login node: computer where user connects + interacts w/ filesystem (e.g. small tasks like downloading/moving files)
  - Compute node: high-spec computers that run jobs
- Partitions: different types of node setups (e.g. some have more compute, some have more memory, etc)
- Job scheduler: software used to submit commands to run on compute nodes
  - User requests: number of cores, RAM, time to reserve node for, etc
  - Scheduler: adds job to queue
- Filesystem: storage shared across both login and compute nodes
  - Home directory (`/home/user`): default when logging in, store small things like config files/local software
  - Scratch space (`~/scratch`): large-scale temporary storage (e.g. for intermediate storage, like cache, logs, checkpoints) - not backed up
    - Unzip large training data files here before starting

## Submitting/viewing jobs via CLI
- Connect: `ssh <username@hpc-address>`
- Submit job to scheduler: `sbatch <jobscript.sh>`
- See all jobs: `squeue -u <username>`
- See output: `cat slurm-<job id>.out`
- See job info: `sacct --format=JobName,State,Elapsed... -j <job id>`
- Cancel job: `scancel <job id>`
- Transferring file from local to cluster: `scp /path/to/file/to/copy username@cluster.com:/path/to/destination`

## Submitting jobscripts
- `#!/bin/bash`: first line, specifies interpreter to use (for shell script)
- `#SBATCH -o <directory>`: set output directory
- `#SBATCH -p <partition name>`
- `#SBATCH -t <HH:MM:SS>`: specify time to reserve for job
- `#SBATCH --mem=<number>GB`: specify RAM memory for job
- `#SBATCH -J <job name>`: create name for job

> For each command, you can use either `--<full name>` or `-<first letter>` as a shortcut \
> (e.g. `#SBATCH -t 1:00:00` or `#SBATCH --time 1:00:00`)
