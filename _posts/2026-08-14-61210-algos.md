## Theory, runtime, etc:
- O(f(n)): upper bound, satisfied for ALL inputs of size n > n_0
- omega(f(n)): lower bound, satisfied for ONE input for each size n > n_0
- Amortization: any sequence of m ops has total cost <= mT

## Basic data structures:
### Sequence:
- Container ops: build_seq(s), len()
- Static ops: iter_seq(), get_at(i), set_at(i), set_at(i, x), index_of(x)
- Dynamic ops: insert_at(i, x), delete_at(i), insert_first(x), delete_first(), insert_last(x), delete_last
- Special case interfaces: stack, queue, deque (both ends)
- Implementation: AVL property can be useful, track relative positions

### Set:
- k/v pairs, unique keys
- Container ops: build(s), len()
- Static ops: find(k)
- Dynamic ops: insert((k, v)), delete(k)
- Order ops: iter_ord(), find_min, find_max, find_next(k), find_prev(k)
- Implementation: array
    - find, delete, etc have O(n) runtime but can be shorter if array is sorted
    - AVL 

### Stack:
- Ops: push, pop, isEmpty, peek
- Implementations:
    - Linked list: pointer to top of stack, O(1) insert/delete/peek using that pointer
    - Array/dynamic array: push data to end of array

### AVL tree
- Properties: skew = 0 or 1, max height $O(\log n)$
- AVL property can be restored with $\leq$ 2 L/R rotations
- Use cases: AVL BST is good for quick insert/delete/find due to height (e.g. implementing sets)

- (AVL) tree augmented with size attribute
    - Rank of x: x.left.size + 1
    - Augmentation should be $O(1)$ - can calculate from L and R augmentations

### Interval tree
- Implementation (AVL BST):
    - Key by x.low
    - Augment with M (max node.high) for ALL nodes in x's subtree
        - x.M = max(x.high, x.left.M, x.right.M)
    - Typical $O(\log n)$ insert/delete based on x.low
- interval_search(T, i):
    - Goal: search for any interval overlapping with interval i
    - start at x = root
    - while x doesn't overlap i:
        - if x.M < low(i): search x.left
        - else: search x.right

> BST range query involves finding keys that fall within a certain interval. If root.val is within the interval, recurse on both children. If it's not in the interval, only need to recurse on one child. Optionally, if we're trying to find a best/worst value within the given range, we can add it as an augmentation.

## Graphs
- Simple graph: no duplicate edges, no self-loops
- Representing graphs:
    - Adjacency matrix: $O(\lvert V \rvert^2)$ space, bad for sparse graphs
    - Adjacency list: $O(\lvert V \rvert + \lvert E \rvert)$ space
        - Put all vertices in a DAA/hash table, each vertex should have a corresponding DAA/linked list which stores all outgoing edges

### BFS
- Solves: single-source shortest path (SSSP)
- Returns: for each vertex, shortest distance to source and path of pointers back to source

> **SSSP(G, s):**
> - Create data structures: $L_i$ (list of all vertices a distance i away from source), $\delta$ (map of vertex : distance), $P$ (mapping of parent : vertex)
> - Base case: $L_0 = \\{s\\}$
> - For each vertex a distance i away, add all adjacent vertices if not traversed yet and update data structures accordingly
>
> <div style="white-space: pre; font-family: monospace; background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">for $u \in L_i$:
>     for $v \in Adj(u)$:
>         if $\delta[v] = \infty$:
>             $L_{i+1}$.add(v)
>             $\delta(v) = i+1$
>             $P[v] = u$</div>

### DFS
- Solves: single source reachability
- Returns: for each vertex, a path of pointers back to source (not necessarily shortest path)

> **SS_reachability(G, s):**
> - Create data structures: $P$ (mapping of parent : vertex)
> - Base case: $L_0 = \\{s\\}$
> - For each vertex a distance i away, add all adjacent vertices if not traversed yet and update data structures accordingly
