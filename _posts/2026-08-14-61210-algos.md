## Basic data structures:
### Sequence
- Container ops: `build_seq(s)`, `len()`
- Static ops: `iter_seq()`, `get_at(i)`, `set_at(i)`, `set_at(i, x)`, `index_of(x)`
- Dynamic ops: `insert_at(i, x)`, `delete_at(i)`, `insert_first(x)`, `delete_first()`, `insert_last(x)`, `delete_last`
- Special case interfaces: stack, queue, deque (both ends)
- Implementation: AVL property can be useful since we only care about relevant positions/ordering, don't need BST property since it doesn't need to be sorted

### Set
- k/v pairs, unique keys
- Container ops: `build(s)`, `len()`
- Static ops: `find(k)`
- Dynamic ops: `insert(k, v)`, `delete(k)`
- Order ops: `iter_ord()`, `find_min`, `find_max`, `find_next(k)`, `find_prev(k)`
- Implementation: array
    - `find`, `delete`, `insert`, etc have $O(n)$ runtime but can be shorter if array is sorted
    - AVL BST could be useful since it's also sorted

### Stack
- Ops: `push`, `pop`, `isEmpty`, `peek`
- Implementations:
    - Linked list: pointer to top of stack, $O(1)$ `insert`/`delete`/`peek` using that pointer
    - Array/dynamic array: `push` data to end of array

### Hashing
**Creating hash tables:**
- Might have keys in a very large range, n. Hash functions map the keys to a much smaller range, m << n
- All keys stored in a DAA of size m so it can directly get/modify the values corresponding to the hashed key
- Hash table operations have $O(1)$ *expected* runtime because there may be collision (i.e., 2 keys mapping to the same hash)
    - Solution: store a chain of elements of size L with the same hash. If L is small, iterating through them takes negligible $O(1)$ time.

**Finding, inserting, deleting element from a hash table by index:**
1. Apply hash function, $O(1)$
2. Get chain at desired index, $O(1)$
3. Find/insert/delete in $O(L)$ time, where L = length of chain

### Heaps and priority queue
- Compact binary tree: all levels filled as much as possible from left to right
    - Implemented using an array, parent/children indeces can be calculated (no need to keep pointers)
- Max heap: key of parents $\geq$ key of both children (children can be unordered)
    - Priority queue: set of elements with a key indicating its priority, implemented using max heap
- Heap implementation:
    - $A[0] = \infty$
    - Store size attribute

### Interval tree
- Implementation (AVL BST):
    - Key by x.low
    - Augment with M (max node.high) for ALL nodes in x's subtree
        - x.M = max(x.high, x.left.M, x.right.M)
    - Typical $O(\log n)$ insert/delete based on x.low
- interval_search(T, i):
    - Goal: search for any interval overlapping with interval i
    - start at x = root
    - while x doesn't overlap i:
        - if x.left.M < low(i): search x.right
        - else: search x.left

> BST range query involves finding keys that fall within a certain interval. If root.val is within the interval, recurse on both children. If it's not in the interval, only need to recurse on one child. Optionally, if we're trying to find a best/worst value within the given range, we can add it as an augmentation.

### BFS
- Solves: single-source shortest path (SSSP)
- Returns: for each vertex, shortest distance to source and path of pointers back to source
- Runtime: $O(\lvert V \rvert + \lvert E \rvert)$

> **BFS_reachability($G$, $s$):**
>
> *Note: This BFS version only solves reachability but does not track distance or path*
>
> - Create data structures:
>   - $Queue$
>   - $Visited$ set
> - Base case: $Queue = deque([s])$, $Visited = \\{s\\}$
> - If vertex not in $Visited$: mark visited and add children to $Queue$
>
> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> for $u \in Queue$:
>   for $v \in Adj(u)$:
>       if $v \notin Visited$:
>           $Queue$.append($v$)
>           $Visited$.add($v$)
> all nodes in $Visited$ are reachable from $s$
{: .prompt-info }

> **BFS_SSSP($G$, $s$):**
>
> *Note: This BFS version keeps track of distances and paths to solve SSSP*
>
> - Create data structures:
>   - $L_i$: list of all vertices a distance $i$ away from source, also serves the purpose of a queue
>   - $\delta$: map of (vertex : distance), also serves the purpose of a visited set
>   - $P$: mapping of (vertex : parent)
> - Base case: $L_0 = \\{s\\}$, $\delta$(all vertices except s) = $\infty$ and $\delta(s) = 0$, $P(s) = None$
> - For each vertex a distance $i$ away, add all adjacent vertices if not traversed yet and update data structures accordingly
>
> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> for $u \in L_i$:
>     for $v \in Adj(u)$:
>         if $\delta[v] = \infty$:
>             $L_{i+1}$.add($v$)
>             $\delta(v) = i+1$
>             $P(v) = u$
{: .prompt-info }

### DFS
- Solves: single source reachability
- Returns: for each vertex, a path of pointers back to source (not necessarily shortest path)
- Runtime: $O(\lvert V \rvert + \lvert E \rvert)$

> **DFS($G$, $s$):**
> - Create data structures:
>   - $P$: mapping of (vertex : parent), also serves the purpose of a visited set
> - Base case: $P(s) = None$
> - For each vertex, keep traveresing deeper while next vertex has not been visited
>
> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> for $v \in Adj(s)$:
>   if $v \notin P$:
>       $P(v) = s$
>       DFS($v$)
{: .prompt-info }

### Kosaraju-Sharir
- Solves: find all SCCs
- Returns: vertices in each SCC
- Runtime: $O(\lvert V \rvert + \lvert E \rvert)$

- Strongly connected components (SCC):  directed, exists $u$-$v$ and $v$-$u$ path
- FullDFS($G$): run DFS on $G$ until all vertices in $G$ have been explored
- Finishing time: for vertex $v$, time at which $v$ and all outgoing edges have been explored in fullDFS
> Consider a graph $G$ with SCCs $A \to B$: $A$ has a larger finishing time than $B$, and $B$ is a sink
> 
> For a DAG, the topological order (if a $u \to v$ edge exists, $u$ comes before $v$) is the reverse finishing order of fullDFS

> **kosaraju_sharir($G$)**
> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> Reverse edges in $G$ to get $G_{rev}$
> Run fullDFS on $G_{rev}$ and record finishing times
> while $G$ and $G_{rev}$ not empty:
>     Find $C_{sink}$ = vertex w/ largest finishing time (this SCC can't reach any vertices outside $C_{sink}$)
>     Run fullDFS on $C_{sink}$
>     Remove $C_{sink}$ from $G$ and $G_{rev}$</pre>
{: .prompt-info }

### Dijkstra's
- Solves: SSSP for non-negatively weighted graphs
- Runtime: $O(\lvert V + E \rvert \log\lvert V \rvert)$

> **dijkstra's($G$, $s$)**
> - Set $d(s) = 0, d(v) = \infty \; \forall v \in V$
> - Build $PQ$ w/ entries $(v, d(v)) \; \forall v \in V$
>
> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> while $PQ$ not empty:
>     delete $(u, d(u))$ for minimum $d(u)$ (path from $s$ to $u$ is fully relaxed, no shorter path exists)
>     $\forall v \in Adj^+(u)$:
>         relax($u$, $v$): set $d(v) = min(d(v), d(u) + w(u, v))$
>         if $d(v)$ changed, update $parent(v) = u$</pre>
{: .prompt-info }

> Dijkstra's only works for non-negative edges. Consider a minimum distance path, $u \to v$. If all edges are non-negative, that must be the globally shortest path. But if there is some path $u \to w \to v$ containing a negative weight, then that path might end up being shorter, which would cause the algorihtm to fail.

### DAG relaxation
- Solves: SSSP for DAG w/ postive or negative weights
- Runtime: $O(\lvert V \rvert + \lvert E \rvert)$

> DAGs always have a SP since they have no cycles, and therefore cannot have negative weight cycles
> Edges in a DAG must be relaxed in topological order, otherwise updates to previous vertices will affect downstream paths connected to that vertex

> **dag_relaxation($G$, $s$)**
> - Set $d(s) = 0, d(v) = \infty \; \forall v \in V$
> - Topo sort vertices in $G$
>
> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> for each $u \in V$, in topo order:
>     $\forall v \in Adj^+(u)$:
>         relax ($u$, $v$)</pre>
{: .prompt-info }


### Bellman Ford
- Solves: SSSP for any graph w/ positive or negative weights, negative cycle detection
- Runtime: $O(\lvert V \rvert \lvert E \rvert)$

- Simple shortest path: contains at most $\lvert V \rvert - 1$ edges (no repeat vertices, which would imply existence of a cycle)
- k-edge distance: $\delta_{k}(s,v)$ = SP from $s$ to $v$ using $\leq k$ edges

> If $\delta_{\lvert V \rvert}(v) < \delta_{\lvert V \rvert - 1}(v)$, $v$ must be a negative cycle witness. This is because adding more edges (that have already been traversed) cannot decrease the distance, unless we are re-traversing a negative edge. In tha case, we have looped back to a negative edge, thus implying the existence of a negative weight cycle. If $G$ has no negative weight cycles, $\delta_{\lvert V \rvert - 1}(s, v)$ is the length of the simple SP.

> **bellman_ford($G$, $s$)**
> - Create DAG $G'$: duplicate $G$ $\lvert V \rvert + 1$ times, with each $v_k \in G'$ representing the k-edge distance from $s$ to $v$ $\forall k \in [0, \lvert V \rvert ]$
>     - $O(\lvert V \rvert \lvert E \rvert)$ size
>
> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> Run dag_relaxation($G$, $s_0$) to obtain $\delta(s_0, v_k) \; \forall v_k \in V$
> if $\delta_{\lvert V \rvert}(v) < \delta_{\lvert V \rvert - 1}(v)$ for ANY $v \in V$:
>     report negative weight cycle
> if no negative weight cycle:
>     shortest path $\forall v \in V$ is $d(s, v) = \delta(s_0, v_{\lvert V \rvert - 1})$</pre>
{: .prompt-info }

### Johnson's algorithm
- Solves: APSP for any graph w/ positive or negative weights
- Runtime: $O({\lvert V \rvert}^2 \log\lvert V \rvert + \lvert V \rvert \lvert E \rvert)$

**Step 1:** Handle negative weight cycles
> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> Find SCCs and construct condensation graph (Kosaraju)
> for each SCC:
>     identify if it has negative weight cycle (Bellman Ford)
> for each edge in $H$:
>     if outgoing/incoming from an SCC with a negative weight cycle:
>         weight = -1
>     else:
>         weight = 0</pre>
> Run DAG APSP on H: any 2 SCCs that are connected and go through a negative SCC will be found since APSP forces them to go through the paths with weight -1, if possible
> for each SCC (A):
>   for each SCC (B):
>       if A and B are connected by a negative SCC:
>           Set distance between all nodes in A and B to be $-\infty$
> remove all negative SCCs to obtain graph G'
{: .prompt-info }

> Now, G' is a normal graph with no negative cycles. We can run the rest of the algorithm on G'.

**Step 2:** Reweight all edges to have non-negative weight
- Goal: transform $G$ to $G'$ with all non-negative edge weights, while preserving SPs
- Approach: there are many possible paths from $s$ to $v$. Thus, to preserve the SP, we need to increase the weight of any $(s, v)$ by some path-independent constant. We can do this by adding $\phi(u)$ to all outgoing edges and subtracting $\phi(u)$ from all incoming edges $\forall u \in V$. Note that this yields $w'(u, v) = w(u, v) + \phi(u) - \phi(v) \; \forall u, v$, where $\phi(u) - \phi(v)$ is a constant. This is because $\phi$(all edges between $s$ and $v$) will cancel out since there will always be one incoming and outgoing edge for those in-between edges.

> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> Create supernode $s$ connected to all vertices, with weight 0
> Let $\phi(v) := \delta_{s}(v)$
> $\forall v \in V$, add $\phi(v)$ to all outgoing edges and subtract $\phi(v)$ from all incoming edges</pre>
{: .prompt-info }

> $w'(u, v) = w(u, v) + \phi(u) - \phi(v) \geq 0$, since we always have $\delta_{s}(v) \leq w(u, v) + \delta_{s}(u)$ by the triangle inequality

**Step 3:** run Dijkstra from every node on reweighted graph, then reverse the reweighting to obtain the actual SP distance between all pairs of nodes
> If the pair of nodes were initially connected by a negative SCC, disregard this result and set to $-\infty$


### All-pairs reachability
- Solves: all pairs reachability for a directed unweighted graph
- Runtime: $O({\lvert V \rvert}^{\omega} \log \lvert V \rvert$, where $\omega$ depends on time for matmul

- Let $A$ = adjacency matrix (with all 1's on diagonal)
> $A^{l}(u, v)$ counts the number of $(u, v)$ paths of length $l$

> **all_pairs_reachability($G$)**
> <pre style="background: rgba(128,128,128,0.08); border-radius: 6px; padding: 0.75em 1em; overflow-x: auto;">
> $k = 1$
> while exponent hasn't reached $\lvert V \rvert$:
>     Repeatedly square $A$ to compute $A$, $A^2$, $A^4$... $A^{\lvert V \rvert}$
>     Make all positive entries 1 (for reachability, # of paths doesn't matter)
> $\forall u, v$, $(u, v)$ path exists if $A^{\lvert V \rvert}_{u, v} > 0$</pre>
{: .prompt-info }

## Dynamic programming
- Greedy choice property: there exists $\geq 1$ optimal solution containing the greedy choice, and the locally optimal greedy choice can always be extended to a globally optimal solution
    - Swapping argument: assume solution S, prove you can swap with GC to get S' which is at least as optimal as S

### Memoization (DP)
1. Define memo M: what each entry represents
2. Define relationships between entries of M: how entries can be calculated as a function of other entries
3. Topological order: relationships between entries should be a DAG, and M can be filled in iteratively in some topological order
4. Define base cases in M
5. Identify how solution can be found using entries of M
