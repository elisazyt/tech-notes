**VMs:**

- VM: isolated computing environment with its own CPU, memory, networking, storage, etc.
- Virtualization: creating virtual (software-based) versions of resources; allows for efficient use of computing hardware (e.g., creating multiple VMs on a single hardware device)
- [Hypervisor](https://aws.amazon.com/compare/the-difference-between-type-1-and-type-2-hypervisors/): creates and manages VMs by partitioning + scheduling requests to hardware resources (e.g., # of cores, memory, etc.)
  - Handles high-level resource sharing (e.g., scheduling when each VM gets to use the physical CPU), but does NOT handle how the partitioned resources are used (e.g., how much CPU to assign to heap/stack/etc., how to split resources between processes, etc.)
  - Can do some dynamic resource allocation, but typically has a hard limit
- Type 1 (bare metal): directly requests/schedules VM resources to the hardware (usually a server)
  - Microkernel: has basic kernel functionalities (e.g., memory allocation, process scheduling, etc.) which can be custom defined
  - NOT a full OS – e.g., no CLI/GUI
- Type 2 (hosted): VM resources scheduled against host OS, which then handles hardware allocation
  - Manually create a VM + install a guest OS
  - E.g., VMWare, Oracle VirtualBox, etc.
- Type 1 hypervisors are more efficient and secure (not exposed to OS vulnerabilities), often used for cloud applications
- [System vs. process VM](https://www.scalecomputing.com/resources/exploring-uses-benefits-and-types-of-virtual-machines):
  - System VM: full VM; each runs its own OS but shares physical computing resources b/n VMs
  - Process VM: runs a single process inside a host OS; creates a platform-independent programming environment which allows the same code to be run on any machine
    - Designed for a specific high-level programming language
    - Often converts code to a universal IR that can be translated into various types of machine code (compatible with many types of underlying OS/hardware)
    - Created when the process starts and destroyed when it exits
    - E.g., any machine with JVM can run Java code
